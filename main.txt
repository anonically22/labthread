LabThread Site Architecture & Documentation

Welcome to LabThread! 

# How data is stored
Since LabThread is designed as a backend-free site, all the dynamic data (Blog posts, Email tips, Author bio, and Site settings) is managed purely on the client-side and stored in the browser's `localStorage`.

The keys used are:
- `labthread_posts` (Blog manager)
- `labthread_tips` (Tips manager)
- `labthread_author` (Author Bio editor)
- `labthread_settings` (Site Settings)

Because it uses `localStorage`, your edits are saved locally to your device/browser. If you want to make edits public or persist them permanently on a new machine, you would need to replace the seed data in `src/utils/blogStore.js`, `src/utils/tipsStore.js`, `src/data/authorData.js`, and `src/utils/settingsStore.js` with the JSON from your localStorage.

# How to access the Admin Panel
Navigate directly to `/admin` in your browser. 
If you aren't logged in, you will be redirected to `/admin/login`.

# Security
- Admin sessions expire automatically after 4 hours and are stored in `sessionStorage`. Closing the browser tab clears the session.
- The password hash is securely managed via `bcryptjs`. 
- Rate limiting prevents brute force guessing by locking out attempts after 3 failures for 60 seconds.

# Ask Form Obfuscation
Nupur's actual email address (`palnupur.2003@gmail.com`) is never placed as plaintext inside the source code bundle to prevent bots from scraping it. Instead, the Ask Form obfuscates it and constructs the `mailto:` string securely in memory at the exact moment the user clicks "Send".

# Making updates
When you add a blog post or email tip using the Admin Panel, no new physical markdown files are created. It simply gets saved to localStorage. The `/blog` and `/tips` routes instantly re-render by reading from localStorage.
